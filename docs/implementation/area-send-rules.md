# Area の送信ルールと空 Area の処理

[文書一覧](../README.md) · [コア仕様](../../SPEC_CORE.md)

## 生成と実行の接続

実行側は [send_rule.lua](../../src/n_tracs_soyabridge/send_rule.lua)、生成側は [generate_area_track.js](../../build/generate_area_track.js) と [compile_send.js](../../build/compile_send.js)。

`generate_area_track.js` は、`res/area_track.json` の送信 DSL を `compile_send.js` で変換し、`send_rule.lua` の関数で送信条件の木を組み立てる。生成物の `res/area_track.lua` は直接編集しない。

`send_rule.lua` は現在 `res/utils.lua` を参照する。Core との接続には、軌道回路・信号の状態の読み出しと、共通タイマーの操作を使う。

## 条件木の評価

同じ階層のブロックは、設定順に評価する。

- `B` は、一致すると同じ階層の後続を評価しない。`P`（`/through`）は後続へ進む。
- 親の行は、子が一つも選ばれなかったときに送る。子の行が nil でも、子が選ばれた事実は残る。

## 軸がない場合

- `C`：`Area.axles` が空なら、送信条件の木を評価せずに戻る。
- `D`：すべての照査点の監視 `W` を実行したあと、軸がなければ送信条件の木だけを省く。
- `W`：軸がなくても、稼働中のタイマーを `0 < timer < hold + dt` の間だけ進める。未始動のタイマーは始めない。軸があれば、照査点の通過による再始動も処理する。

軸があるときは、毎周期その時点の条件で送信する。同じ値が続いても送信を省かない。`before_broadcast` は、すべての Area のコールバックを呼ぶ。

## 生成時に省く条件木

コンパイラは、ブロック自身と子に送信行があるかを調べる。木全体に送信行がないときだけ、その条件木と、その木でしか使わない条件関数の定義を除く。照査点の監視がなければ共有の空の関数を生成し、あれば `D` と `W` を残す。

送信がある木の途中の `nil` 行は除かない。条件に一致した `nil` 行には、後続のブロックと親の送信を抑止する意味がある。子が行を省略したときに親から継承する動作も保つ。

変換対象の DSL では、条件は状態の読み取りだけに使い、状態の更新は照査点の監視などに分ける。条件の評価に副作用を持たせると、空 Area や送信行のない木では実行されなくなる。

## 元の Lua を使う場合

次の場合は、エディタが書き出した元の Lua コールバックをそのまま使う。軸がないときも呼ぶ。

- 任意の Lua を含む、未対応の記述
- 複数の `send_parts`
- 変換用の情報がない場合

`SoyaBridge:before_broadcast()` は、コールバックの戻り値を `cbdata` に保存する。

## 検証

どちらも Windows 側の `pnpm test` で実行する。

- `tests/repro_send_rule_empty.lua`：本番のジェネレータで合成データを生成し、次を確認する。合成データは `tests/fixtures/generate_empty_send_rules.js` にある。
  - 空、在線、再び空への遷移
  - タイマー監視
  - 送信行のない木と、途中の `nil` 行
  - 元の Lua へのフォールバック
- `tests/repro_send_rule.lua`：本番データを変換したものと元の Lua を、送信値とタイマー操作について比較する。
