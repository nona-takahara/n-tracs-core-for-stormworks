# 軌道回路予約方式と本実装

[文書一覧](../README.md) · [コア仕様](../../SPEC_CORE.md)

予約情報は [Track](../../src/n_tracs_core/track/track.lua) が持ち、[Signal](../../src/n_tracs_core/signal/signal.lua) と [Switch](../../src/n_tracs_core/switch/switch.lua) が参照する。状態遷移と判定式は [SPEC_CORE.md](../../SPEC_CORE.md) にある。

## 本実装の状態と処理

| 観点 | N-TRACS Core の実装 |
|---|---|
| 区間の情報 | `Track` が、在線情報、`book`・`bookDest`、関係てこ名、方向、前要素の参照などを持つ |
| 二つの予約フィールド | メインの `book` は仮予約・進路鎖錠・発点予約、サブの `bookDest` は着点予約・過走防護区間の本予約を表す |
| 予約の適合判定 | `is_ready_for_book_temporary()`・`is_ready_for_book_start()` などが、既存予約の状態と方向を確認する |
| 仮予約 | `Signal:bookTemporary()` が、必要な適合条件を先に確認してから書き込む |
| 本予約 | `Signal:process()` が、仮予約の確認と ASR などの条件を合わせて、発点予約・進路鎖錠・着点予約・過走防護区間の本予約を確定する |
| 鎖錠の確認 | `Signal` が、進路と過走防護の成立を確認する。`Switch:getWLR()` は、関連軌道回路の在線とメイン予約から転換の可否を判定する |
| 予約の共用 | 同方向の着点予約、同方向の進路鎖錠などを、用途ごとに判定する |
| 予約の解放 | 予約状態に応じて、自区間の非在線、前要素の予約状態、信号てこの ASR、タイマーなどを参照する |

## 変更時に維持する条件

- `book` と `bookDest` は、用途・所有てこ・方向・前要素を別々に持つ。片方が `NoBook` でも、軌道回路全体が空きとは限らない。
- 予約できるかの判定と、自進路の本予約が成立したかの確認は別である。互換性のある既存予約を使えるので、「仮予約を確認できる」ことは、自てこの `Temporary` があることと同じではない。
- 予約の書き込み関数は、呼び出し側の確認を前提にしている。`Signal` の処理を通さずに単独で呼ぶときは、同じ条件を満たす必要がある。
- 状態は `Track` → `Signal` → `Switch` の順にその場で更新する。周期の開始時のスナップショットを全オブジェクトが共有する方式ではない。同種のオブジェクトの処理順は保証しない。
- 解放条件は状態ごとに違う。発点予約（`Start`）の ASR 参照、進路鎖錠（`RouteLock`）の非在線と前要素、着点予約の時間条件を、一つの共通条件にまとめない。

在線情報は `Track:before_process()` で受け取る。Stormworks 上の Area と検知点から在線を作る処理は、[Soya Bridge](soya-bridge.md) が担当する。

## 過走防護の扱い

`RouteOver` は過走防護区間の本予約（サブフィールド）で、通常は着点予約を前要素として参照する。着点予約が `DestinationActive` から `DestinationExpired` に進むと、後続の解放判定を進められる。タイマーの満了と、着点予約そのものの解放は別の状態変化である。

`overrunLockFallback` は、進路自体の本予約と HyR が成立する経路を広げる。HR の成立条件は緩めない。現示番号はコールバックが決める。条件の詳細は [コア仕様の4.7節](../../SPEC_CORE.md#47-過走防護フォールバックoverrunlockfallback--hyr) にある。
