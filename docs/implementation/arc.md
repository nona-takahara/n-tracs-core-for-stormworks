# ARC（自動進路制御）の実装

[文書一覧](../README.md) · [検査](arc-check.md) · [利用・設定](../usage/arc-usage.md)

実行時の本体は [arc.lua](../../src/n_tracs_arc/arc.lua)。Soya Bridge が Core 演算のあとに呼び、ARC が出したてこ入力は次の Core 演算で処理される。設定検査は [arc_check.lua](../../src/n_tracs_arc/arc_check.lua) がビルド時に行い、実行時には行わない。

## 構築時のデータ

`Arc.new(config, nt, probe)` は `parse`・`train_id`・`probe` を保持し、駅ごとの要求・到着記録・索引と、予約資源の所有情報を初期化する。

- `watch`：構築時の全軌道回路IDをソートした一覧。駅間も観測する。
- `registration_index`：`match.at`、最初の動きの `start_point`、`early.start_point` から、sequence番号を引く索引。
- `sequence_order`：sequenceから設定順の番号を引く索引。

構築後に軌道回路、sequences、登録点を変えても、索引は自動では更新されない。指令値の形式と識別子は `parse`・`train_id` が定義する。

## 1周期の更新順序

`Arc:process()` は `clock` を1増やし、次の順に更新する。

| 順序 | 処理 |
|---|---|
| 1 | `observe()`：全軌道回路の指令値を読み、識別子ごとの観測位置と、軌道回路から列車への逆索引を作る |
| 2 | `release_reservations()`：所有列車の位置・方向条件に従って、予約資源を解放する |
| 3 | 駅ごとに `update_arriving()` → `accept()` → `update_moves()` を実行する |
| 4 | その駅が `running` なら、`judge()` で候補を採用し、てこ入力を出す |
| 5 | `detect_deadlock()` で、その駅の警報を更新する |

駅は `pairs()` で走査するので、駅どうしの処理順は保証しない。停止中の駅でも、新規受付・既存要求の更新・警報判定は続く。停止フラグが止めるのは `judge()` による採用だけで、Core がすでにかけた鎖錠は取り消さない。

## 観測と候補検索

`parse(probe(track_id))` の結果から、`train_id()` で識別子を得る。同じ識別子が複数の区間に現れたときは、一つの観測に位置をまとめる。物理的な列車を個別に追跡する仕組みではないので、別の列車に同じ識別子を与えると区別できない。

sequenceの候補は、観測位置の索引と現在のsequenceから集める。重複を除き、設定順に `match.accept()` を評価する。観測対象全体を絞り込む最適化は行わない。

逆索引は、資源上の待ち相手の特定に使う。複数の列車が資源を塞いでいるときは、観測の `pairs()` 順を記録して選ぶため、識別子の昇順などは保証しない。

## 要求と採用状態

| 状態・条件 | 更新 |
|---|---|
| 未登録 | 登録候補が適合し、入線中の抑止がなければ、要求を作る |
| 未採用 | 指令値を更新する。最初の動きでは、sequenceの変更・不適合による削除も行う |
| `requested` | てこ入力を出した状態。次の更新で `isRouteLocked()` の成立を確認したら `locked` にする |
| `requested` で未鎖錠・未進入 | 採用を解除し、候補へ戻す |
| `locked` で `enter` に進入 | 次の動きへ進む。最後の動きなら要求を削除し、必要なら到着記録を作る |
| `locked` で未進入のまま解錠 | 採用を解除し、要求を除外する |
| 観測から消失 | 未採用または除外済みの要求を削除する。採用済みの要求は、消失だけでは削除しない |

- `locked` は進路自体の鎖錠を確認した状態で、過走防護や HR の成立までは表さない。
- `seen` は、登録以降に観測した位置を記録する。制御開始点を通過済みか判断するために使う。
- 先出しした次の動きは `pre` に保持し、現在の動きが完了したときに引き継ぐ。先出しの鎖錠が成立しないとき、または解けたときは、`pre` を取り消す。

## 資源と競合

`resource_busy()` は、資源内の各軌道回路について、在線、他てこのメイン予約、他てこのサブ予約を確認する。自てこの予約は塞がりに数えない。これとは別に、採用候補の進路がすでに鎖錠されているときは待つ。

候補は、繰り上げ指定、`class`、前周期に塞がった着線を空ける補正、登録番号の順に整列する。各候補では、`options` の設定順に選択肢を試す。同じ周期に採用した資源と着線も、競合判定に反映する。

ARCの予約資源は、列車識別子を所有者として保持し、`hold`・`take`・`free` と解放条件で制御する。Core の `BookType` とは別の状態である。所有列車が観測から消えただけでは、自動では解放しない。

## ロックと警報

着線・使用資源の在線列車、予約資源の所有者、待ち一覧の先行要求から待ち相手を求め、循環を警報として記録する。単独の列車が留まって後続を塞ぐ場合は、互いを待つ循環とは区別する。

待ち一覧は、先行する競合要求を後続が追い越すのを防ぐ。ただし、先行要求がその後続列車の在線を待っているときは、後続を抑止しない。新しい循環を作らないための例外である。

警報は検出結果にとどまる。列車の移動、要求の取り消し、Core の解錠は自動では行わない。`alerts` の参照と手動操作は [利用文書](../usage/arc-usage.md#停止再開と手動操作)、検証の範囲は [検査文書](arc-check.md) にある。

## 到着の直後の入換（時間差）

最後の動きの選択肢が `settle` と `dest` を持つときは、動きの完了時に `arriving[key] = {dest, at = nil}` を作る。観測位置が着線資源に入った周期を `at` に記録する。`at == nil` の間は、新規要求の登録を抑止する。

次の動きが `wait` を持ち、到着記録があるときは、`clock - at >= wait * 10` になるまで採用を待つ。記録がなければ待たない。待ち時間は `process()` の呼出し回数で計り、10呼出し/秒を固定で仮定している。到着記録は、入換を採用したとき、または観測から列車が消えたときに削除する。

計時が始まるのは、指令値を持つ先頭側の検知点が着線に進入したときである。最後尾の進入や、列車全体の停止は判定していない。

## 列選に用いる指令値と表示用の送信

指令値による選別は、`parse` と設定の適合条件で行う。運転士向けの表示用の送信は、次の経路で行う。

| データ | 生成・送信 |
|---|---|
| 軌道回路の指令値 | `VehicleInfo:send()` が `<軌道回路>_ARC_L/R` へ送る。ARCの採用状態とは独立している |
| 採用中の動きの指令値 | `Arc:adopted_values()` が、通常採用・先出しのてこ名に `req.arc.raw` を対応づける |
| 到着後に wait を持つ未採用要求 | 除外されておらず、到着記録があり、選択肢が一つなら、そのてこ名にも値を載せる |
| 信号機側の配信 | `SoyaBridge:arc_process()` が上の表を `arc_values` に置き、`VehicleInfo:send()` が `<てこ名>_ARC` へ送る。値がなければ0 |

- 採用中の指令値は更新しない。動きの完了後は、その採用に由来する値を載せない。
- `adopted_values()` の出力はてこ名をキーにする。複数の要求が同じてこへ値を書いたときの優先順は保証しない。
- 信号機側のARC送信には、対象の `sign` と Dial/Keypad が必要。ビークルが読み込む条件は `_ASPECT` と共通で、`N-TRACS RESET` または登録済みエイリアスを使った部品名で認識する。
- アドオン側では、停止現示による ARC 値のマスクは行わない。表示の合成と可視条件は、ビークル側の処理である。
