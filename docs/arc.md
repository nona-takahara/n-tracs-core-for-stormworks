# ARC（自動進路制御）

列車の ARC 指令値を読み、駅ごとの設定に従って進路てこを自動で扱う。
指令値の形式は [宗弥急行プロジェクト ARC](https://nonasaba.net/sw-train-docs/support/Soya-Express-ARC.html) にある。
進路を作る順序の規則（要求・「動き」・資源・クラス・予約資源など）は「宗弥急行 ARC 制御仕様」を実装したもので、この文書は設定の書き方と、実装が仕様に付け足した点・足りない点だけを書く。

ARC 指令値の受信は従来どおり `Axle` が行う（`{検知名}_ARC` ダイヤルを読む）。ARC はそれを軌道回路ごとに引くだけで、受信の仕組みは変えない。

## 構成

| 場所 | 役割 |
|---|---|
| `src/n_tracs_arc/arc_value.lua` | 7桁の指令値（運行番号・上下線・種別・行先）の分解 |
| `src/n_tracs_arc/arc.lua` | 判定のエンジン。駅の知識を持たず、設定と N-TRACS の状態だけで動く |
| `res/arc.lua` | 駅データ（手書き）。`sw:create_arc{...}` に設定を渡す |
| `SoyaBridge:track_arc` / `arc_process` | 軌道回路上の車軸から指令値と速さを引く。`onTick` の Phase 4 で ARC を回す |

ARC は N-TRACS の演算が確定したあと、次の演算の前（Phase 4）に動く。出した進路要求は次の演算で処理される。

## 設定の書式

```lua
sw:create_arc({
    stop_speed = 0.5,             -- この速さ(m/s)以下なら停車とみなす。省略時 0.5
    reservations = {              -- 駅をまたぐ予約資源
        ["掘戸線"] = {
            -- 持ち主が at 上に現れ、指令値の上下線が b と一致したら放す。b を省くと上下線を問わない
            release = { { at = { "NHB5LT" }, b = 2 } },
        },
    },
    stations = {
        NHB = {
            code = 3,             -- 行先の駅コード（指令値 dd の十の位）
            running = true,       -- false なら停止状態で始める。省略時 true
            resources = {         -- 資源名 → 軌道回路ID
                ["3番"] = { "NHB5LT" },
                ["単線部分"] = { "NHB13RT", "NHB23T", "NHB22AT", "NHB21T" },
            },
            sequences = { ... },  -- 「一連の動き」。上から順に照合し、最初に合ったものを使う
        },
    },
})
```

### 「一連の動き」

```lua
{
    id = "上り終着",
    match = {
        at = { "TKM_NHB1T" },     -- 必須。列車がここのどれかにいるとき登録する（登録点、またはホーム）
        b = 1,                    -- 上下線。省略すると問わない
        dest = "terminal",        -- "terminal": 行先がこの駅 / "through": 他の駅 / "unspecified": 行先無指定
        pullin = false,           -- 行先の下位桁が9（引き上げ線）か。省略すると問わない
        category = { 0 },         -- 種別の一の位の分類 0:一般 1:試運転 2:臨時 3:回送 4:その他
        class = { 5 },            -- 種別の十の位
    },
    moves = { ... },              -- 「動き」。1つ以上
}
```

行先が無指定（`dest = "unspecified"`）のときにどう動くかも設定が決める。該当する `sequences` がなければ ARC は何もしない。

### 「動き」

```lua
{
    class = 1,                    -- 必須。ソートのクラス。小さいほど先に判定する
    start_point = "NHB_TKM1T",    -- 制御開始点。列車がここに現れるまで採用しない
    from = "3番",                 -- 出発元のホーム（資源名）
    enter = { "NHB13RT" },        -- 必須。信号の内方。列車がここに現れたら「動き」は済んだ
    options = { ... },            -- 必須。進路の選び方。先に書いたもので準備できたものを使う
}
```

- 制御開始点がなく `from` がある「動き」（始発・折り返しの出発）は、列車が `from` のホームに停車していることが準備の条件になる。
- `from` は、同じホームに着く待ちが詰まっているとき、その「動き」を同じクラスの先頭に出す補正にも使う。補正は直前の判定で分かった待ちを使う。

### 進路の選び方

```lua
{
    signal = "NHB4L",             -- 必須。進路を要求するてこ
    platform = 4,                 -- 行先の番線。指令値で番線が指定されたとき、合わない選択肢を外す。0（自動選択）と9（引き上げ線）は外さない
    uses = { "単線部分" },        -- 使う資源
    dest = "4番",                 -- 着線（資源名）。在線がなく、ほかの進路の着線でもないことが準備の条件
    reserve = { name = "掘戸線", mode = "take" },  -- "hold": 持っていること / "take": 採用時に取る / "free": 空いているときだけ使う（取らない）
}
```

起動時に、設定が参照する軌道回路・てこ・資源・予約資源が存在するかを確認する。存在しなければ `[ARC:駅名]` 付きのエラーで止まる。

## 運用

`?nt arc` は管理者のコマンド。CTC 卓の操作に相当する。

| コマンド | 内容 |
|---|---|
| `?nt arc <駅> start` / `stop` | 駅の ARC を再開・停止する。停止中も受付と「動き」の更新は続く |
| `?nt arc <駅> list` | 要求の一覧（運行番号:一連の動き#動き/採用の印）と、動けなくなる組み合わせの警報 |
| `?nt arc <駅> promote <運行番号>` | 要求を一回限り先頭に繰り上げる |
| `?nt arc <駅> restore <運行番号>` | 除外した要求を戻す |
| `?nt arc <駅> remove <運行番号>` | 要求を削除する |
| `?nt arc release <予約資源>` | 予約資源を手で放す |

記憶（要求・登録番号・予約資源の持ち主・停止状態）はセーブ・ロードで消える。消えたときは上のコマンドで立て直す。

## 仕様との差と制限

- **運行番号がない指令値（pp = 0）は扱わない。** 要求は運行番号で列車を見分けるので、運行番号のない列車には要求を作らない。
- **駅データは未同梱。** `res/arc.lua` の `stations` は空で、ARC は何もしない。北港・高見が丘の駅データは、減速を促す信号と制御開始点の位置が駅ごとの未決事項であること、掘戸町の駅データと予約資源「掘戸線」を共有することから、この変更には含めていない。
- **鎖錠の確認は `Signal:isRouteLocked` で行う。** 仕様の「次の周期になっても鎖錠されていない」を、そのまま次の周期で判定する。転てつ器の転換が遅れて鎖錠が遅れる間は、要求済みの印が外れては再度付く。てこの入力は付いたままなので進路は進む。
  その間に自分の予約で資源が塞がって見えないよう、資源の使用中の判定は、その進路自身のてこによる予約を数えない。
- **「小さな」登録点の取りこぼし。** 制御開始点を過ぎたかは、観測した軌道回路に一度でも現れたかで見る。ARC が見る間隔（6 tick）より短くしか在線しない軌道回路を制御開始点にすると、取りこぼす。
- **終着した列車の指令値が残っていると、同じ指令値で再登録されうる。** 終着ホームを `match.at` に含む「一連の動き」は、`dest` で終着と通しを分けて、再登録に合わないようにする。
- **ここまで、実機（Stormworks）では動かしていない。** テストも書いていない。構文はビルドで確認した。

## 設定例（北港・上り終着の一部。推定であり検証していない）

`res/signal.toml` の `NHB4L`（TKM_NHB1T → NHB4LT）・`NHB5L`（TKM_NHB1T → NHB5LT）から、仕様の「上り終着」を書き起こした形。
制御開始点は仕様が駅ごとの未決事項としているため、置いていない。

```lua
NHB = {
    code = 3,
    resources = {
        ["3番"] = { "NHB5LT" },
        ["4番"] = { "NHB4LT" },
        ["単線部分"] = { "NHB13RT", "NHB23T", "NHB22AT", "NHB21T" },
        ["掘戸線"] = { "HLT_NHB1T" },
    },
    sequences = {
        {
            id = "上り終着",
            match = { at = { "TKM_NHB1T" }, b = 1, dest = "terminal" },
            moves = { {
                class = 2,
                enter = { "NHB13RT" },
                options = {
                    { signal = "NHB4L", platform = 4, uses = { "単線部分" }, dest = "4番" },
                    { signal = "NHB5L", platform = 3, uses = { "単線部分" }, dest = "3番",
                      reserve = { name = "掘戸線", mode = "free" } },
                },
            } },
        },
    },
},
```
