# Area の送信ルールと空 Area の処理

`build/generate_area_track.js` は、`res/area_track.json` の送信 DSL を
`build/compile_send.js` で変換し、`src/n_tracs_soyabridge/send_rule.lua` の関数で
送信条件の木を組み立てる。生成物の `res/area_track.lua` は直接編集しない。

## 軸がない場合

- `C`: `Area.axles` が空なら、送信条件の木を評価せずに戻る。
- `D`: すべての照査点の監視 `W` を実行したあと、軸がなければ送信条件の木だけを省く。
- `W`: 軸がなくても、稼働中のタイマーを従来の上限条件で進める。未始動のタイマーは始めない。軸があれば照査点通過による再始動も処理する。

軸がある場合は、毎周期その時点の条件で送信する。同じ送信値が続いても送信を省略しない。
`before_broadcast` はすべての Area のコールバックを従来どおり呼ぶ。

## 生成時に省く条件木

コンパイラは、ブロック自身と子に送信行があるかを調べる。
木全体に送信行がない場合だけ、その条件木と、その木でしか使わない条件関数の定義を除く。
照査点の監視がなければ共有する空の関数を生成し、監視があれば `D` と `W` を残す。

送信がある木の途中にある `nil` 行は除かない。条件に一致した `nil` 行は、
後続のブロックや親の送信を抑止する意味を持つ。子が行を省略した場合の親からの継承も維持する。

変換対象の DSL の条件は状態の読み取りに使い、状態の更新は照査点の監視などに分ける。
送信条件の評価に副作用を持たせると、空 Area や送信行のない木では実行されなくなる。

## 元の Lua を使う場合

任意 Lua を含む未対応の記述、複数の `send_parts`、変換用の情報がない場合は、
エディタが書き出した元の Lua コールバックをそのまま使う。
これらは軸がない場合も呼び出し、戻り値の `cbdata` への保存も継続する。

## 検証

- `tests/repro_send_rule_empty.lua`: 本番ジェネレータで合成データを生成し、空・在線・再び空への遷移、タイマー監視、送信行のない木、途中の `nil` 行、元の Lua へのフォールバックを確認する。合成データは `tests/fixtures/generate_empty_send_rules.js` にある。
- `tests/repro_send_rule.lua`: 本番データを変換したものと元の Lua を、送信値とタイマー操作について比較する。

どちらも Windows 側の `pnpm test` で実行する。
